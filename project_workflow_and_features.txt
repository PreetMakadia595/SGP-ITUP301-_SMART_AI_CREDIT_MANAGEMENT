1. PROJECT OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
The "Smart AI Credit Management and Utilization Advisor" is a full-stack AI platform
governance and credit tracking web application. It features an automated Hybrid Data
Collection System that automatically ingests AI usage information across three
independent data sources, processes it through a unified deduplication layer, updates
an automated Machine Learning forecasting pipeline, and provides real-time credit
exhaustion predictions and optimization recommendations.

Architecture Flow:
                  
                    User / Web Browser
                            │
               ┌────────────┼────────────┐
               │            │            │
               ▼            ▼            ▼
        Official APIs   Chrome Ext.   Manual Entry
        (OpenAI, etc.) (7 Websites)    (Fallback)
               │            │            │
               └────────────┼────────────┘
                            ▼
             Data Synchronization Layer
         (Normalize, Deduplicate, Validate)
                            ▼
              Database (PostgreSQL / SQLite)
           (CreditUsageLog, IngestedEvent, etc.)
                            ▼
              Automated ML Prediction Engine
          (scikit-learn & XGBoost Regressors)
                            ▼
           Dashboard & AI Advisor Recommendations

2. HYBRID DATA COLLECTION SYSTEM (3 DATA SOURCES)
================================================================================

SOURCE 1: OFFICIAL AI PROVIDER APIs
-----------------------------------
- Integrates via official REST APIs for key providers:
  1. OpenAI API (Models: gpt-4o, gpt-4o-mini, o1-preview, o3-mini)
  2. Anthropic API (Models: claude-3-5-sonnet, claude-3-opus, claude-3-5-haiku)
  3. Google Gemini API (Models: gemini-1.5-pro, gemini-1.5-flash, gemini-2.0-flash-exp)
  4. Perplexity API (Models: sonar, sonar-pro, sonar-reasoning)
  5. Extensible Provider Factory (Open/Closed principle for future AI providers)
- Key Capabilities per Provider:
  * Connect (Credential Validation & Encryption)
  * Disconnect (Clears stored secrets)
  * Sync Usage (Fetch active prompt counts & token usage)
  * Sync Billing (Fetches credits; displays "Not Supported" if provider API doesn't expose billing)
  * Sync Subscription (Fetches active plan & renewal status)
  * Sync Models (Fetches list of available provider models)
  * Background Sync (Background job sync)
- Encryption: Fernet 256-bit symmetric encryption at rest. Keys masked in responses.


SOURCE 2: CHROME BROWSER EXTENSION (MANIFEST V3)
------------------------------------------------
- Directory: /extension
- Supported AI Web Platforms:
  1. chatgpt.com
  2. claude.ai
  3. gemini.google.com
  4. perplexity.ai
  5. cursor.com
  6. bolt.new
  7. lovable.dev
- Responsibilities:
  * Active Site & Model Detection via DOM watchers and selectors
  * Active Session Duration Tracking (Heartbeat timer)
  * Prompt Count Tracking (Submit click listeners & Enter key interceptors)
  * Timestamp & Page URL Context capturing
  * Secure JWT Authorization header communication with backend (/api/v1/ingestion/extension-event)
  * PRIVACY GUARANTEE: Does NOT collect prompt text contents by default.
  * Extension Popup UI for JWT authentication token pairing.


SOURCE 3: MANUAL ENTRY (FALLBACK)
---------------------------------
- Used when automatic API/extension tracking is unavailable.
- Inputs: Platform name, Model name, Project name, Task type, Credits used, Prompt count, Token usage, Usage date, Notes.
- Ingested directly through the unified Data Synchronization Layer.

4. BACKEND ENDPOINTS & CORE SERVICES
================================================================================

AUTH ROUTES (/api/v1/auth)
- POST /register         : Register new user
- POST /login            : Login & receive JWT access + refresh tokens
- POST /refresh          : Refresh expired access token

USER ROUTES (/api/v1/users)
- GET  /me               : Fetch current user profile
- PATCH /me              : Update user profile
- POST /change-password  : Update account password

PLATFORM ROUTES (/api/v1/platforms)
- GET  /supported        : List 8 supported AI platforms catalog
- GET  /                 : List user's managed platforms
- POST /                 : Add platform subscription & encrypted API key
- PUT  /{id}             : Update platform details
- DELETE /{id}           : Remove platform
- GET  /{id}/reveal-key  : Decrypt and reveal API key

PROVIDER SYNC ROUTES (/api/v1/providers)
- GET  /status           : Get connection status, masked keys, & billing capability for all providers
- POST /connect          : Connect provider with encrypted API key & initial sync
- POST /disconnect       : Disconnect provider
- POST /sync/{provider}  : Run sync for a single provider
- POST /sync-all         : Manual Sync Button endpoint (syncs all connected providers)
- GET  /history          : Retrieve sync execution audit logs

DATA INGESTION ROUTES (/api/v1/ingestion)
- POST /extension-event  : Ingest telemetry from Chrome Browser Extension (JWT authenticated)
- POST /manual           : Ingest manual entry through Data Synchronization Layer
- GET  /source-breakdown : Return percentage & count breakdown by source (API vs Extension vs Manual)
- GET  /latest-events    : Return real-time stream of ingested usage events

CREDIT LOG ROUTES (/api/v1/credits/logs)
- GET  /                 : List credit usage logs with search, filter & pagination
- POST /                 : Create credit log entry
- GET  /charts           : Get aggregated daily, weekly, monthly chart data
- GET  /{id}             : Get single credit log
- PUT  /{id}             : Update credit log
- DELETE /{id}           : Delete credit log

ANALYTICS & ML ROUTES (/api/v1/analytics)
- GET  /overview         : Total credits, total cost, services tracked
- GET  /trends           : 30-day usage trends
- GET  /ml               : Run ML prediction engine & return exhaustion date + forecasts

5. SECURITY & DATABASE ARCHITECTURE
================================================================================

SECURITY & ENCRYPTION
- Password Hashing: bcrypt (via passlib).
- API Key Encryption: Fernet 256-bit URL-safe symmetric key derived from JWT secret.
- Secret Exposure Safeguard: API keys are masked (e.g. sk-proj...1234) in API responses.
- Authentication: Short-lived JWT Access Tokens (30 min) + Long-lived Refresh Tokens (7 days).

DATABASE TABLES (PostgreSQL / SQLite)
1. users                 : User credentials, full name, avatar, superuser flags.
2. user_platforms        : Connected platform credentials, encrypted API keys, sync status, capabilities.
3. credit_entries        : Summarized per-service credit balances, total cost, remaining credits.
4. credit_usage_logs     : Detailed credit usage logs (platform, model, project, task type, prompts, tokens, usage_date).
5. ingested_usage_events : Raw telemetry events from API, Extension, Manual entries with unique sync_hash deduplication.
6. sync_history          : Audit log of synchronization job runs.
7. ai_services           : Catalog of supported AI services.
